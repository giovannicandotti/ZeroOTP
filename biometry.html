What is PRF, and where does my data actually live?

What PRF is

PRF (Pseudo-Random Function) is a WebAuthn extension. Normally a passkey only ever answers yes/no: "this user passed verification." PRF lets a site hand the authenticator a salt and get back HMAC-SHA256(credential-bound-secret, salt) — a 32-byte value that's deterministic (same credential + same salt = same output, always) but impossible to reproduce without the physical authenticator and a successful Touch ID / Windows Hello / Android biometric check. That output is what gets fed into HKDF-SHA256 to derive the AES-256-GCM key that actually protects your TOTP secret.

Where the encrypted data lives

In localStorage, under the key bioVaultRecord — a JSON blob holding the AES-GCM ciphertext, its IV, and two non-secret salts. Never cleartext at rest. In the primary "prf" mode, the AES key itself is written nowhere: it's re-derived fresh from a new PRF output every time you unlock. See js/biometric.js for the full implementation, including its weaker fallback "gate" mode for authenticators without PRF support.

Does macOS support PRF?

Yes — macOS 15 (Sequoia) or later, via passkeys held in iCloud Keychain, on Safari 18+, Chrome 132+, or Firefox 139+. One open caveat: that confirmed support is specifically for the iCloud Keychain path. When Chrome creates a passkey it may offer to save it to Google Password Manager instead (cloud-synced to your Google account) — whether that separate store returns PRF output the same way on macOS isn't something this page assumes. Use "check support" below to see what your own setup actually reports.
