How this fits: NIST & Microsoft

ZeroOTP uses two fundamentally different kinds of authenticator, and the two current frameworks below score them very differently. This is a factual mapping against NIST SP 800-63B-4 (2025) and Microsoft Entra's Conditional Access authentication strengths — not a certification of this project.

MethodNIST SP 800-63B-4Microsoft Entra strength
Cookie / LocalStorage / Password Manager (TOTP) Software OATH token — AAL2, but not phishing-resistant MFA strength only
Biometric / passkey (PRF mode) Syncable passkey — AAL2, genuinely phishing-resistant Phishing-resistant MFA strength

In short: the three TOTP-based backends are the same authenticator type by NIST's definition — a shared secret — and all land at the same tier. Only the Biometric method's primary (PRF) mode is phishing-resistant; its fallback “gate” mode is not cryptographically bound to the passkey and shouldn't be treated as equivalent (see js/biometric.js).

Full mapping, methodology, and links to the primary NIST and Microsoft sources: compliance.html (or the raw COMPLIANCE.md).

Known limitations

  • Low PBKDF2 iterations (Cookie / LocalStorage only): 6,000 iterations, intentionally low for demo speed. NIST's current guidance calls for substantially more — treat this as a demo value, not a production one.
  • Hardcoded salt (Cookie / LocalStorage only): the PBKDF2 salt is a fixed string baked into the source rather than randomized per device or retrieved from a server.
  • No Master Password complexity check (Cookie / LocalStorage only): any string is accepted, with no minimum length or strength requirement enforced.
  • One entry per backend — partially resolved. Cookie, LocalStorage, and the Biometric vault each store exactly one Issuer/Secret pair. Chrome Password Manager is the exception: it already manages multiple entries for this origin natively, offering its own account picker to choose between them — this is exactly how the multi-account detection in ZeroOTP's guided page works today. So this limitation still stands for three of the four backends, but no longer for Password Manager.
